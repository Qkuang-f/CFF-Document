项目文档

本项目是基于DLL组合的方式开发的框架。DLL之间可以单向依赖，最终组合成目标框架。

本项目并非只开发一个框架，而是开发多框架设计。例如游戏基础框架：Game框架、状态帧同步框架、战斗系统。

多个框架之间肯定需要用到同样的代码库，而一个游戏开发并不需要重复的代码库。

因此，真正做游戏时，选取多个框架，导出框架用到的DLL，合并DLL。

例如做Action游戏，需要导出Game、Act战斗系统。如果做卡牌游戏，那么需要导出Game、卡牌战斗系统。导出的同时把框架用到的DLL一并导出。

内容划分

  • 核心部分：框架的重要部分。

    dll库是多个程序集，其他一个程序集。除DLL库外，其他框架可以由Editor和Runtiem的区分。

    各dll之间没有所属关系，只有依赖关系，因此，不会嵌套命名空间。

    • QKLibrary：DLL库，自写、三方代理、三方库
    • QKGame
    • QKSFSync：状态帧同步
    • QKACTSystem

  • 辅助部分：和游戏内无关

    • 辅助工具：如，作者署名和日期更新、DLL导出工具
    • Demo代码：测试代码

命名：库的名称和命名空间加QkF前缀，内部名称无所谓。

项目规划

  • QkF：框架命名空间，所有的路径在其下。

    • 一类型一文件，除非私有类型。
    • 多少情况只需要QkF命名空间。特殊如下：
    • QkF.Edit：编辑器

  • DLL：其下各种库

    • Runtime：Runtime类型核心代码
    • Edit：Editor类型核心代码
    序号 dll规则
    1 API返回类型约束（详见下）。若是私有返回随意。主要避免外界使用时，无意用到三方类型。
    2 API返回途径：类型、接口、类型成员、方法参数与返回值、继承父类型、实现接口类型
    3 UnityAPI：禁止返回不稳定类型；允许返回常用稳定的类型。例如：Vector2。
    4 代理三方库：允许使用三方库实现功能，但不允许直接返回三方库的API类型。（未来替换三方库，只用维护代理库）
    5 Editor类型库：允许直接返回Unity.Editor的API
    6 Runtime禁止继承UnityAPI，尤其是Mono

  • Game：基础游戏框架

    • Runtime：运行时
    • Edit：编辑器，导出时非编辑器

  • ACT：动作游戏框架

    • Runtime
    • Edit

  • EditTool：编辑器工具

    • 和任何框架无关，只是单纯的辅助编辑器工具

注：只有DLL中的代码会导出成dll。Game.Runtiem这种不会。因为在设计上，核心代码都会是DLL的形式存在，Runtime和Editor只是调用DLL库，并且提供少量的外置逻辑。

项目命名规范

所有类型全部在QkF命名空间下。所有工具路径全部在QkF路径下。

QkF命名前缀或路径，除了宣誓所属，还有避免冲突的作用。

ACT设计

帅锅Game

如果ACT设计需要用到Game中的内容，则帅锅。例如，Act需要加载预制体。而资源加载肯定是Game控制，例如热更等。

那么Act就不管资源加载，提供一个预制体池，act系统直接从这个池拿取预制体就行。测试阶段写测试代码填充对象池即可。真正游戏时，需要Game和Logic代码去填充此对象池（预加载）
